# PJ49 — Jarvis Agent Orchestrator

Status: Founder-locked build doctrine
Parent: PJ48 — Jarvis Memory Vault
Issue: #29

## Purpose

PJ49 creates the Jarvis Agent Orchestrator.

The Orchestrator coordinates Jarvis internal specialist roles so one Commander request can move through intent, command, policy, tool routing, knowledge, live data, source confidence, evidence, and final answer composition.

## Core Law

Jarvis may coordinate internal roles, but Jarvis may not become an uncontrolled swarm.

One Commander request equals one governed orchestration plan.

Every orchestration step must map to one of these governed layers:

- Intent Router
- Command Registry
- Policy Gate
- Tool Router or Adapter Selector
- Knowledge Brain
- Live Data Router
- Source Confidence Engine
- Memory Vault
- Evidence Ledger
- Answer Composer
- Visual HUD

## What the Orchestrator Does

The Orchestrator must:

- normalize the Commander request,
- choose internal roles,
- create a step plan,
- enforce phase order,
- block unknown role/tool chains,
- call only approved runtime modules,
- collect evidence,
- return a final Commander-facing answer,
- surface status to HUD and voice.

## What the Orchestrator Must Not Do

The Orchestrator must not:

- create unknown agents at runtime,
- bypass policy gate,
- bypass command registry,
- call tools directly from free text,
- chain risky actions without approval,
- treat memory as live truth,
- claim success without evidence.

## Final Rule

Jarvis becomes powerful through disciplined orchestration, not uncontrolled autonomy.

The Orchestrator coordinates Jarvis. Kingsmen law controls Jarvis.
