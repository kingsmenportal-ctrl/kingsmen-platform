# AGENTS-01 — Agent Authority Boundary

## Authority Order

1. Founder approval
2. Backend policies
3. PostgreSQL truth
4. Validator reports
5. PowerShell/GitHub proof
6. AI/agent recommendations

AI agents are never the final authority for:
- payments
- refunds
- official application status
- document verification status
- source verification
- partner identity sharing
- production deployment
- growth cap increase
- stop-selling override
- secrets handling

## Command Safety Classes

### SAFE_READ

Allowed without approval:
- show reports
- show build status
- show provider status
- show next action

### SAFE_DRAFT

Allowed without approval:
- draft founder action packet
- draft candidate-safe message
- draft school outreach copy
- draft support explanation

### APPROVAL_REQUIRED

Requires founder approval:
- deploy
- enable live payment
- send bulk email
- change DNS
- raise cap
- unfreeze source
- partner identity sharing
- production database change

### BLOCKED

Blocked until a later validated layer:
- raw shell from browser
- uncontrolled AI agent execution
- candidate data export
- payment approval by AI
- refund approval by AI
- official submission claim without proof
