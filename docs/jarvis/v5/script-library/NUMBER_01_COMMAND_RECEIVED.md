## 9. Policy-gate role

The policy gate must run immediately after command receipt and classification.

Policy gate checks:

- Is the Commander authorised?
- Is this a public/candidate route? If yes, block Jarvis exposure.
- Is the command asking for secrets? If yes, block or redact.
- Is the command asking for raw private data? If yes, protect.
- Is the command asking to send, publish, deploy, mutate database, delete, or commit? If yes, require correct approval/proof.
- Is the command asking for current facts? If yes, require live verification.
- Is the command asking for payment or official status? If yes, require provider/official proof and avoid authority claims.
- Is the command asking for production readiness? If yes, require runtime/test/deployment evidence.

Number 01 must therefore not imply action is allowed. It only confirms the command has been received for disciplined processing.

Correct wording:

> Command received, Commander. I shall inspect the policy boundary before execution.

Wrong wording:

> Command received, executing now.
