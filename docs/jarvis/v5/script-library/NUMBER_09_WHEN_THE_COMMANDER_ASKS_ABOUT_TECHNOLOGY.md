## 3. Difference between Number 09 and Number 10

Number 09 is Technology.

Number 10 is Coding.

Technology asks:

- What tool should we use?
- How should this system be designed?
- Should Kingsmen use this platform?
- Is this architecture clean?
- What is the safest integration path?
- What technology belongs in the stack?

Coding asks:

- Inspect this code.
- Fix this file.
- Write this implementation.
- Repair this TypeScript error.
- Create this route.
- Correct this component.

Examples:

- “Should we use Airtable here?” → Number 09.
- “Fix the Airtable API code” → Number 10.
- “What is the right voice architecture for Jarvis?” → Number 09.
- “Create the voice API route” → Number 10.
- “Is Supabase right for this?” → Number 09.
- “Write the Supabase migration” → Number 10.

Number 09 may lead to Number 10, but it does not skip straight into code unless the Commander asks for implementation.

Policy checks:

- Does this technology expose private data?
- Does it bypass backend authority?
- Does it allow uncontrolled automation?
- Does it require secrets/API keys?
- Does it write to the database?
- Does it submit forms or official actions?
- Does it affect payments or official statuses?
- Does it increase cost beyond free/low-capital discipline?
- Does it create useless layers?
- Does it require current documentation verification?
- Does it need validators before implementation?
- Does it require Commander approval before build/deploy?

Rules:

- backend controls state,
- PostgreSQL remains Truth Vault,
- Airtable remains mirror-only,
- n8n remains thin worker-only,
- Playwright remains scout-only,
- OpenClaw remains gateway-only,
- browser must not directly control database or local machine,
- secrets must not be exposed,
- current documentation must be verified when tool behaviour may have changed,
- no production claim without runtime evidence.
