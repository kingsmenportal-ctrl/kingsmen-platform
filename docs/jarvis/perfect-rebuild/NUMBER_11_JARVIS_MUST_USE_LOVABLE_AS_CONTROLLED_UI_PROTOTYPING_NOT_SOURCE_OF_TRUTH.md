## 1. Original meaning preserved

Number 11 means Lovable may assist Kingsmen and Jarvis, but Lovable must never become Jarvis itself, never become the source of truth, never override GitHub, never override Kingsmen doctrine, and never replace the Commander-controlled repo.

Lovable is useful for fast UI exploration, visual prototyping, screen concepts, web app surfaces, landing pages, command cockpit ideas, mobile views, and fast iteration. But the permanent Kingsmen system must remain controlled by GitHub repo files, backend policy, validators, evidence, and the Commander doctrine.

The correct rule is:

Lovable may help create or explore the visual expression of Jarvis.
GitHub remains the permanent repo record.
PostgreSQL remains internal truth.
Jarvis doctrine remains the authority.
Validators prove whether the result is acceptable.
The Commander decides whether any Lovable output is accepted.

Lovable must never be treated as:

- Jarvis identity owner,
- doctrine authority,
- production proof by itself,
- backend truth,
- candidate data store,
- secret store,
- final repo source,
- uncontrolled public Jarvis,
- replacement for GitHub,
- replacement for validators,
- replacement for policy gates,
- replacement for the Commander.

Number 11 locks Lovable as a controlled creative/building surface under Jarvis, not above Jarvis.
