# Jarvis Visual System Lock

Authority: Commander pasted record, Issue #36.
Status: locked for implementation.

## Core visual law

The locked Jarvis visual reference is not a wallpaper to decorate with unrelated add-on cards.

It is the visual identity of the live Kingsmen Jarvis system.

## Required behavior

Jarvis must become:

- full functional system
- working clickable interface
- speaking interface
- listening interface
- intelligent response surface
- organized command environment
- professional Commander console
- respectful and disciplined assistant
- structured, planned, and evidence-aware Kingsmen control layer

## Visual implementation rules

1. Do not replace the locked futuristic Kingsmen Jarvis look with generic dashboards.
2. Do not add unrelated cards on top of the visual reference as if the reference is only background.
3. The visual language must become the actual system shell.
4. The command input, voice orb, evidence drawer, build status, runtime status, and command deck must feel native to that visual system.
5. Text must be high quality, clear, professional, and Commander-grade.
6. Jarvis must preserve Kingsmen command-house identity.
7. Jarvis must not drift into plain ChatGPT UI.

## Current remote reality

The current GitHub Jarvis page renders `JarvisAgentClient` at `/jarvis`. The current client includes a HUD, mission cards, command deck, voice command button, visual feed toggle, approval box, messages, live output, evidence drawer, and HUD surface list.

That is not enough. The next implementation must transform these parts into a unified Jarvis operating system surface.

## Acceptance rule

A future Jarvis screen is accepted only when the Commander can say it looks and behaves like the locked Jarvis system, not like a wallpaper with interface pieces placed on top.
