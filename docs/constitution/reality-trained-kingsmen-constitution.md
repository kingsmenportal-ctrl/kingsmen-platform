# Reality-Trained Kingsmen Constitution

Status: BUILT_PENDING_VALIDATION  
Batch: BATCH 01 — Merge Foundation  
Date: 2026-06-01

## 1. Supreme identity

Kingsmen is a South African movement operating system. It helps users move through study, TVET, SETA and learnership routes, internships, apprenticeships, employment, NSFAS support, bursaries, accommodation, CV readiness, documents, source verification, proof tracking, MAP fallback, Human-Step Handoff, Phoenix fallback, partner and accommodation-owner supply, school guidance, and founder-governed operations.

Kingsmen must not be narrowed to only a website, university applications, accommodation, CV writing, jobs, OpenClaw, Playwright, n8n, Airtable, or social media. Those are parts of the system, not the system.

## 2. Creation law

ChatGPT designs. GitHub preserves. PowerShell Creator materializes. Validators prove. Reports explain. Control Plane governs. PostgreSQL stores truth. Oracle Lite runs the first constrained deployment. OpenClaw may assist later as a governed operator gateway.

A thing is not complete because it was discussed in chat. It becomes real only when the repo contains the file, the validator checks it, the report records it, and the correct proof status is assigned.

## 3. Proof ladder

Use these statuses exactly:

- NOT_STARTED
- DESIGNED
- BUILT_PENDING_VALIDATION
- VALIDATED
- RUNTIME_PROVEN
- STAGING_PROVEN
- PRODUCTION_READY
- PRODUCTION_ACTIVE
- PAUSED
- REPLACED
- ARCHIVED_FOR_FUTURE

ChatGPT may design. GitHub files may become BUILT_PENDING_VALIDATION. Passing validators and reports may mark VALIDATED. Runtime and staging proof must come from actual execution.

## 4. Oracle Lite law

Oracle Free / Oracle Lite is the default deployment constraint. The first production architecture must prefer Docker Compose, low concurrency, PostgreSQL truth, Redis queue discipline, Nginx, log pruning, backups, email-first communication, limited Playwright, OpenClaw sandboxing, and cost-aware scheduling.

The starting cap is 500 active candidates. The cap limits active volume, not Kingsmen intelligence. All users must see the core route brain. Packages alter quantity, speed, monitoring intensity, human depth, SLA, escalation, and support intensity.

## 5. Package access law

Every candidate must have access to the core Kingsmen route brain:

- Higher Education
- TVET
- SETA / Learnership
- Internship
- Apprenticeship
- Employment
- NSFAS support where relevant
- Bursary readiness
- Accommodation support where relevant
- Source verification
- Document readiness
- Proof tracking
- MAP
- Human-Step Handoff
- Phoenix fallback

Packages must not hide these gates. They may only change active managed quantity, priority, monitoring, SLA, human depth, manual fallback intensity, and reporting.

## 6. Communication law

Email is the primary communication nervous system. WhatsApp is urgent-only and ceremonial, never routine bulk reminders. SMS is backup-only. All candidate-facing claims must match runtime proof. If email is not configured or not delivered, the UI must not claim that email was sent.

## 7. Source-confidence law

Kingsmen must separate official truth from public leads, social rumours, old posts, aggregators, and user-submitted names. Fees, deadlines, payment instructions, funding status, accommodation deposits, current openings, official statuses, and success stories require verified evidence and the correct approval level.

## 8. Reality-learning law

Kingsmen must learn from public reality, competitors, official sources, users, support tickets, outcomes, social demand, accommodation markets, job boards, schools, partners, and tools. It may adapt public patterns. It must not steal code, copy protected branding, copy exact private UI, scrape private pages, bypass CAPTCHA/OTP, impersonate institutions, or publish unverified claims.

## 9. Tool law

Every tool must be registered with purpose, status, allowed actions, forbidden actions, wake trigger, sleep trigger, Oracle impact, credential requirement, fallback, report path, and kill switch. Tools wake, do allowed work, write proof, and sleep. They do not control Kingsmen.

## 10. OpenClaw law

OpenClaw is a governed remote operator gateway, not the Kingsmen brain. It may read reports, run safe validators, draft GitHub issues, summarize source leads, check Oracle health, and prepare founder action packets. It must not access raw secrets, raw candidate documents by default, production database writes, real unapproved messages, payments/refunds, pricing changes, cap increases, production deploys, or CAPTCHA/OTP bypass.

## 11. Accommodation law

Accommodation is a full Kingsmen sector. Kingsmen may collect accommodation needs, verify owners/listings, match route-linked demand, and facilitate consent-based introductions. Kingsmen does not handle rent payments, guarantee landlord approval, share candidate contact without consent, or show unverified listings as verified.

## 12. CV Revamp law

CV Revamp is locked at R49.99 as a low-cost entry product. If a CV Revamp user upgrades to any Kingsmen package, the upgrade grants +2 active managed applications/routes on top of the selected package quantity. CV Revamp must not invent fake qualifications or fake experience.

## 13. MAP / Human-Step / Phoenix law

If automation is blocked by CAPTCHA, OTP, portal downtime, selector failure, manual-only action, source uncertainty, or risk, Kingsmen must stop unsafe automation and use MAP, Human-Step Handoff, staff task, founder approval, or Phoenix fallback. Kingsmen must never bypass CAPTCHA/OTP.

## 14. Founder governance law

The founder must see what is happening, what is blocked, what is risky, what needs approval, what is safe to automate, what proof exists, and what action is recommended. The Control Plane must govern tools, credentials, providers, source verification, accommodation, growth, cap, revenue, incidents, staff, reports, and build proof.

## 15. Merge law

Existing valid work must be preserved. Incomplete work must be repaired. Unsafe work must be replaced or archived. Chat-only work must be materialized. No module may be marked complete without repo files, validator, report, and appropriate runtime proof.
